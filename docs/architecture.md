# Архитектура бэкенда

Бэкенд сгенерирован из шаблона
[`copier-template-python-backend`](https://github.com/eldenizfamilyanskicode/copier-template-python-backend)
и следует его ролям и правилам (`AGENTS.md`). Здесь — как эти роли применены к
продукту из [концепции](concept.md).

## Роли и направление зависимостей

```
HTTP (FastAPI)            app/gateways/http/      маршруты, коды ошибок, ответы
  └─ operators            app/operators/          одна точка входа на эндпоинт
      └─ pipelines        app/pipelines/          порядок оркестраторов в фазе
          └─ orchestrators app/orchestrators/     координация нескольких use case
              └─ use_cases app/use_cases/         одно бизнес-действие
                  ├─ repositories  app/repositories/  сохранение документов
                  ├─ registries    app/registries/    справочники: страны, языки, ниши, тарифы
                  ├─ facilitators  app/facilitators/  узкие побочные эффекты (SMS, уведомления)
                  ├─ utilities     app/utilities/     детерминированные операции
                  └─ transformers  app/transformers/  преобразование форм
repositories ─ adapters (app/adapters/) ─ clients (app/clients/)  внешние системы
```

- `app/services/` запрещён (тест `test_no_services`).
- Use case зависит от контрактов (`app/contracts/`), а не от конкретных классов.
  Конкретные классы связываются в контейнерах `app/containers/`.
- Контракты ролей — `Protocol`. Use case: `run`, оркестратор: `execute`,
  пайплайн: `start`, оператор: `operate`, трансформер: `transform`.
- Все доменные значения — типизированные примитивы из `app/schemas/typings/`.
  Сырые `str`/`int`/`float` — только на внешней границе до валидации.

## Ограниченные контексты

Примитивы лежат в `app/schemas/typings/<context>/<разрешённое_имя>.py`:

| Контекст | Что внутри |
| --- | --- |
| `localization` | страна (ISO 3166-1 alpha-2), язык (BCP 47), валюта (ISO 4217), часовой пояс (IANA), номер в E.164, экстренный номер |
| `accounts` | владелец, одноразовый код, сессия, почта |
| `businesses` | бизнес, название, адрес, минуты суток для часов работы |
| `niches` | названия и описания шаблонов |
| `questionnaires` | ключи вопросов, ответы, факты, позиции прайса, частые вопросы |
| `billing` | суммы в минимальных единицах валюты, курс |
| `assistants` | версия помощника, системный промпт, автотесты |
| `conversations` | разговор, сообщение, идентификатор собеседника в канале, сырой транскрипт LLM |
| `bookings` | бронь, заявка, ресурс, время, размер группы |
| `handoffs` | передача человеку, вопросы без ответа, контакты менеджеров |
| `channels` | токены и идентификаторы каналов |

## Адаптивность под любую страну

Требование владельца проекта: человек из любой страны регистрируется по номеру своей
страны и собирает себе помощника. Реализация:

1. **Номера телефонов.** Любой ввод (`+995 555 12-34-56`, `8 (999) 123-45-67` с
   подсказкой страны `RU`, `020 7946 0018` с `GB`) разбирается библиотекой
   `phonenumbers` (порт libphonenumber, 245 регионов) и хранится только в E.164.
   Из номера выводятся страна, тип линии и часовые пояса.
2. **Профиль страны** собирается автоматически для каждой страны мира из
   `phonenumbers` (телефонный код) и `Babel`/CLDR (официальные языки, валюта, часовые
   пояса, локализованные названия), а поверх накладываются кураторские данные:
   экстренный номер, стартовые языки (для Грузии — ka, ru, en), предпочтительный
   канал доставки кода входа, наличие местных номеров для помощника, статус
   онбординга, регион обработки данных (по умолчанию — ЕС).
3. **Языки.** Любой тег BCP 47. Реестр знает письменность и направление текста
   (иврит и арабский — справа налево) и честно помечает поддержку голоса:
   `verified`, `beta`, `needs_pilot_check` (грузинский — до пилота), `unsupported`.
4. **Деньги** — целые минимальные единицы валюты + код ISO 4217. Тарифы заданы в
   евро; для валюты страны — явный прайс-лист (₾ из концепции) или пересчёт по курсу.
   Форматирование — через CLDR на языке владельца.
5. **Время.** Часы работы и брони — в часовом поясе бизнеса (IANA), хранение — в UNIX
   секундах UTC. Доля обращений «вне рабочего времени» считается в местном времени.
6. **Тексты владельцу** (анкета, инструкции) — словари `язык → текст` с цепочкой
   отката: запрошенный язык → базовый язык → английский.
7. **Переадресация звонков** — стандартные GSM-коды (`**61*`, `**67*`, `**62*`)
   с номером помощника в международном формате.

## Сквозные потоки

### Онбординг владельца

`POST /v1/auth/otp/start` → разбор номера любой страны → код через канал страны
(SMS/WhatsApp/Telegram/почта) → `POST /v1/auth/otp/verify` → токен сессии.
`POST /v1/businesses` → страна из номера или явная → умолчания страны.

### Анкета → сборка → автотесты → запуск

`PUT /v1/businesses/{id}/questionnaire` → проверка по шаблону ниши → таблица фактов.
`POST /v1/businesses/{id}/assistant-versions` → системный промпт (детерминированно из
шаблона ниши + фактов + правил страны) → версия → автотесты (AI-клиент на каждом
языке бизнеса × сценарии ниши, AI-судья) → `GET .../gaps` («что дописать») →
`POST .../assistant-versions/{version_id}/activate`.

### Разговор

Входящее сообщение любого канала нормализуется в `InboundMessage` →
разговор (закреплён за версией помощника, чтобы системный промпт и набор инструментов
не менялись внутри разговора) → язык по первой фразе → цикл LLM с инструментами
(`check_availability`, `create_booking`, `cancel_booking`, `create_lead`,
`handoff_to_human`, `record_unanswered_question`) → ответ в канал.
Первое сообщение помощника в разговоре всегда раскрывает, что это AI-ассистент.

### LLM

- Модель по умолчанию — `claude-opus-5-5` (меняется переменной окружения), effort
  `low` для чата, `adaptive` thinking по умолчанию модели.
- Серверный fallback при отказе (`fallbacks: "default"`, beta
  `server-side-fallback-2026-07-01`).
- Транскрипт LLM хранится «как есть» (сырые блоки ответа) и только дописывается —
  так сохраняются thinking-блоки и кэш промпта. Изменчивые данные (текущее местное
  время бизнеса) идут в пользовательский ход, а не в системный промпт.
- Тесты используют скриптовый адаптер, сеть не нужна.

## HTTP-слой

- `app/gateways/http/application.py` — `build_http_application(...)` собирает
  FastAPI-приложение из роутеров.
- Роутер каждого раздела — функция `build_<раздел>_router(...)`, которая получает
  готовые операторы аргументами (явная инъекция, без глобальных состояний).
- Исключения приложения (`app/schemas/exceptions/`) переводятся в HTTP-коды в
  одном месте.
- Точка входа: `uv run uvicorn app.main:create_application --factory`.

## Хранилище

Репозитории работают поверх контракта документного хранилища. Сейчас — потокобезопасный
in-memory адаптер (данные живут до перезапуска); следующий шаг — адаптер MongoDB или
PostgreSQL с тем же контрактом, без изменений в use case.
